# DOCUMENTATION AS CODE

Load when durable behavior, architecture, operation or contracts change.

Document knowledge required to understand, operate, modify or integrate the system.

Prioritize WHY over obvious WHAT.

Document when material:
architecture, domains, public APIs, important internal contracts, DB/schema, events/webhooks/jobs, env/config, deployment, integrations, design system, security decisions and invariants.

After code change perform documentation impact analysis.
Do not let docs become false.
Do not create documentation files that merely duplicate another source.
